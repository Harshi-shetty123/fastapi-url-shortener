# FastAPI URL Shortener

A backend application that converts long URLs into short, shareable links using **Python, FastAPI, SQLAlchemy and SQLite**.

The project is built to demonstrate practical REST API development, request validation, database operations, and clean backend code organization.

## Features

### Implemented
- Create short URLs from valid HTTP/HTTPS URLs.
- Generate random, URL-safe short codes.
- Reuse an existing short code when the same original URL is submitted.
- Store URL records in SQLite using SQLAlchemy.
- Validate incoming URLs using Pydantic.
- Return URL details, including the generated short link and click count.
- Automated API tests using pytest.
- GitHub Actions workflow for continuous integration.

### Planned
- Redirect short URLs to their original destinations.
- Track clicks when a short URL is accessed.
- Retrieve a list of created URLs.
- Improve error handling for database and request failures.

## How It Works

1. A client submits an original URL to the API.
2. Pydantic validates the incoming URL.
3. The service checks whether the original URL already exists.
4. If it exists, the existing record is returned.
5. Otherwise, the service generates a random short code.
6. The repository stores the original URL and short code in SQLite.
7. The API returns the saved URL details and generated short link.

## API Documentation

Start the application and open the interactive Swagger documentation:

- Swagger UI: http://127.0.0.1:8765/docs
- ReDoc: http://127.0.0.1:8765/redoc

### Create a Short URL

**Endpoint:** `POST /urls/`

**Request body:**

```json
{
  "original_url": "https://www.example.com/products"
}
```

**Successful response — HTTP 201:**

```json
{
  "id": 1,
  "original_url": "https://www.example.com/products",
  "short_code": "khfEoFU",
  "short_url": "http://127.0.0.1:8765/khfEoFU",
  "click_count": 0,
  "created_at": "2026-10-24T06:58:44"
}
```

The short code and timestamp are generated by the application. The example above illustrates the response structure.

**Validation error — HTTP 422:**

The API rejects invalid URL input.

### Health Check

**Endpoint:** `GET /`

Returns:

```json
{
  "message": "URL Shortener API is running"
}
```

## Database Design

The application uses a SQLite table named `urls`.

| Column | Description |
|---|---|
| `id` | Primary key |
| `original_url` | Original URL, required and unique |
| `short_code` | Generated short identifier, required and unique |
| `click_count` | Number of recorded clicks; initially zero |
| `created_at` | Record creation timestamp |

## Design Decisions

### Separate API, service and repository layers

- **API routes:** Handle HTTP requests and responses.
- **Schemas:** Validate incoming data and define response structures.
- **Services:** Implement application business logic.
- **Repositories:** Perform database queries and persistence.
- **Models:** Define the database structure.

This separation makes the code easier to understand, test and maintain.

### Duplicate URL handling

The application reuses the existing short code when an identical original URL is submitted. This avoids creating duplicate records for the same URL.

### Random short-code generation

The application generates short codes internally using Python's `secrets` module. The database enforces uniqueness, and the service retries when a generated code conflicts with an existing record.

### SQLite and SQLAlchemy

SQLite keeps the project lightweight without requiring a separate database server. SQLAlchemy provides Python-based database access through an ORM.

## Setup Instructions

### 1. Clone the repository

```bash
git clone git@github-personal:Harshi-shetty123/fastapi-url-shortener.git
cd fastapi-url-shortener
```

### 2. Create a virtual environment

```bash
python3 -m venv venv
```

### 3. Activate the environment

Linux/macOS:

```bash
source venv/bin/activate
```

Windows:

```bash
venv\Scripts\activate
```

### 4. Install dependencies

```bash
pip install -r requirements.txt
```

### 5. Run the application

```bash
uvicorn app.main:app --reload --port 8765
```

The API is now available at `http://127.0.0.1:8765`.

## Running Tests

Run the automated test suite from the project root:

```bash
python -m pytest -v
```

The tests currently cover:

- Health-check endpoint.
- Successful short URL creation.
- Duplicate URL handling.
- Invalid URL validation.

The API tests use an isolated in-memory SQLite database so they do not need to modify the development database.

## Continuous Integration

GitHub Actions runs the automated test suite when changes are pushed to the configured branches and when pull requests target `main`.

The workflow:

1. Checks out the repository.
2. Sets up Python.
3. Installs project dependencies.
4. Runs the pytest suite.

This project currently implements **Continuous Integration (CI)**. Automated deployment (CD) is not configured.
